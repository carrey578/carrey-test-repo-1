# 阶段 8 轻量协作规则

> **所属方案：** 基于开发环境 4.5.1 的灵犀-Codex 轻量协作推进方案  
> **当前分支：** work/lingxi-codex-bootstrap  
> **执行环境：** 本地 Windows（Surface）+ Codex CLI  
> **文档性质：** 阶段 8 轻量规则固化文档

---

## 一、阶段 8 定位

阶段 8 不再继续试探能力上限，而是把当前已经验证通过的轻量协作方式，固化成一个：

- 够用
- 可重复
- 低风险
- 随时可收口

的小闭环。

当前阶段 8 的核心目标不是“做更多”，而是“把已经能稳定做成的事说清楚”。

---

## 二、常规可做白名单

当前推荐 Codex 常规承担的任务包括：

1. `docs/collab/chatgpt-lingxi/` 下新增或更新协作文档
2. `README`、handoff 模板、阶段说明、总结文档更新
3. `152-lingxi-codex-session-log.md` 等日志类文档追加记录
4. `tools/*.ps1` 中单文件、仅用户可见文案级修改
5. 轻量 diff 检查、回退建议、提交说明整理

这些任务的共同特点是：

- 文件范围清楚
- 变更可人工快速复核
- 出问题时容易回退
- 不依赖新增基础设施

---

## 三、暂时不要做

当前阶段 8 仍明确不建议让 Codex 直接承担：

1. 多文件联动复杂修改
2. 函数签名、参数名、退出码、路径逻辑改造
3. 脚本判断逻辑大改
4. 主分支直接操作
5. 跨仓库或服务器侧联动修复
6. ACP / 云节点 / 常驻服务类基础设施改造
7. 任何需要引入新 API 计费依赖的扩张性试验

一句话概括：

**阶段 8 只允许“轻量、边界清楚、可快速回退”的任务。**

---

## 四、默认执行流程

后续若有真实轻量任务，默认按下面流程执行：

1. 人工先确认当前分支与工作区干净
2. 明确本轮目标文件和边界
3. 由 Codex 仅在允许范围内执行改动
4. 人工查看 `git diff --name-only` 和目标文件 diff
5. 人工运行本地验收命令
6. 验收通过后再 commit / push
7. 必要时补 session log 或阶段文档

默认不再现场临时编排重型流程，而是尽量复用这条固定轻量路径。

---

## 五、验收标准

阶段 8 之后，每轮轻量任务至少满足以下条件才算通过：

1. 改动范围符合事先定义的文件边界
2. 没有越界修改 `tools/*.ps1` 逻辑或其他非目标文件
3. `.\tools\dev-entry.ps1 help` 正常
4. `.\tools\verify-dev-entry.ps1` 通过
5. `.\tools\repo-health-check.ps1` 通过
6. `git status` 最终回到 clean

若本轮只是纯文档任务，也建议保留后 3 条验收，确认现有轻量协作链仍然稳定。

---

## 六、回退动作

如果 Codex 本轮改动超出边界，优先按最小回退处理：

### 场景 1：还没 commit

```powershell
git restore <目标文件>
git clean -fd
git status
```

### 场景 2：已经 commit 但还没 push

```powershell
git reset --hard HEAD~1
```

### 场景 3：只是网络 / SSH 导致 push 失败

不要改动文档内容，优先修复链路后重推。

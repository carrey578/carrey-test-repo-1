# 113-token-cost-control-policy

## 当前阶段
开发环境配置方案 4.2 启动

## 当前默认原则
1. 默认只使用 Coding Plan
2. 当前默认模型为 MiniMax M2.5
3. Claude / OpenAI / Codex 等外部模型，不得默认常开
4. 灵犀如需调用外部模型，必须先向我申请授权
5. 一次授权，只对应一个具体任务
6. 任务完成后，必须尽快停用外部模型，并恢复默认 Coding Plan 路由

## 1. 当前默认为什么只走 Coding Plan

### 成本考虑
- Coding Plan 属于套餐内模型，边际成本低
- Claude / OpenAI / Codex 按 token 计费，成本可控性差
- 在预算敏感场景下，默认走套餐内模型更安全

### 能力匹配
- 当前默认模型 MiniMax M2.5 已能满足大部分常规开发任务
- 包括：文档生成、脚本草稿、低风险修改、仓库巡检、change summary 等

### 费用控制目标
- 避免模型越开越多、费用越来越高
- 保持"默认低成本 + 授权临时用 + 完成后回退"的费用控制节奏

## 2. 哪些任务默认只能走 Coding Plan

以下任务类型，默认只走 Coding Plan：

| 任务类型 | 说明 |
|----------|------|
| 仓库巡检 | 常规状态检查、文件清理 |
| 文档生成 | README、说明文档、变更摘要 |
| change summary / handoff | 任务交接文档 |
| 脚本草稿 | 一般性脚本、自动化草案 |
| 低风险修改 | docs/、scripts/、tools/ 下的轻量改动 |
| 小功能第一轮 | 首次尝试实现，不涉及复杂逻辑 |
| 常规代码审查 | 简单 code review |

## 3. 哪些任务可以申请外部模型

以下任务类型，可以申请使用外部模型（Claude / OpenAI / Codex）：

| 任务类型 | 说明 |
|----------|------|
| 大仓深度分析 | 仓库规模大、文件多、需要跨文件理解 |
| 跨文件复杂重构 | 涉及多个文件、复杂逻辑调整 |
| 长文档深读 | 超长文档理解、总结、提取 |
| 默认模型多次失败 | Coding Plan 模型尝试后仍无法满足 |
| 关键问题攻坚 | 重要但不复杂的难点问题 |
| 第二意见/对拍 | 需要不同视角的代码审查 |

## 4. 授权前必须满足什么条件

灵犀在申请外部模型授权前，必须满足以下条件：

### 必要条件
1. **任务目标明确** - 能说清楚要做什么
2. **文件范围明确** - 能列出会涉及哪些文件
3. **预计轮数明确** - 能预估需要几轮交互
4. **结束条件明确** - 能说清楚什么时候算完成

### 充分条件（至少满足一条）
1. 任务明显超出 Coding Plan 默认模型能力
2. 任务复杂度高，需要更强推理能力
3. 需要第二意见进行对拍
4. 已有一次 Coding Plan 尝试但效果不理想

### 授权申请格式
```
申请使用外部模型：<模型名称>
原因：<为什么需要外部模型>
任务：<任务名称>
目标文件：<文件范围>
预计轮数：<1~3轮>
预计成本级别：低/中/高
完成后动作：恢复默认 Coding Plan 路由
请确认是否授权。
```

## 5. 任务完成后如何恢复默认低成本路由

### 恢复步骤
1. **记录任务日志** - 记录本次使用的外部模型、任务名称、开始/结束时间
2. **停用外部模型** - 清除外部模型相关的环境变量
3. **恢复默认配置** - 将 `runtime/model-routing/active-provider.env` 恢复到 Coding Plan
4. **更新授权状态** - 将 `external-model-approval.status` 改回 APPROVED=0

### 恢复命令
```bash
bash /root/workspace/config/model-routing/restore-default-route.sh
```

### 恢复后的确认
- 灵犀需回报"已恢复默认低成本路由"
- 确认当前生效模型为 MiniMax M2.5

## 当前允许
- 默认使用 Coding Plan 内模型处理常规开发任务
- 生成 docs / report / change summary / handoff
- 低风险 scripts / tools / docs 修改
- 常规小功能第一轮尝试

## 当前不允许
- 灵犀未授权直接调用 Claude / OpenAI / Codex
- 外部高价模型长期开启
- 把高价模型用于普通重复性 Markdown 生成
- 在任务无明确结束条件时启用外部模型

## 当前例外规则
若任务明显超出 Coding Plan 默认模型能力，灵犀可以发起授权申请；
但未获得明确授权前，不得实际启用外部模型。

## 当前默认回退要求
外部模型任务完成后：
- 记录任务日志
- 停用外部模型
- 恢复默认 Coding Plan 路由
- 回报"已恢复默认低成本路由"

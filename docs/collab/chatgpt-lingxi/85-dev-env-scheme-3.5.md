## 二、当前方案演进状态

### 方案 1.0 的定位（已被后续版本吸收）

方案 1.0 解决的是"本地轻终端 + 云上执行层 + GitHub SSH/OAuth + AI 工具主链路"的基础思路。

核心原则仍然有效：
- 本地 Surface Laptop 4 只做轻开发终端
- 活跃 repo 放在 D 盘
- GitHub 认证走 SSH / OAuth
- OpenClaw 放云服务器执行重任务
- 不把本地堆成重型开发机

### 方案 2.0 的状态

方案 2.0 已经把"规划"推进为"稳定开发基线"。

实际落地关键点：
- ChatGPT Project 已围绕 repo 建立并投入使用
- 腾讯云服务器已形成独立开发工作区与传输区
- GitHub 共享目录已建立并持续使用
- 服务器侧 markdown 文档受控写回 GitHub 已打通
- Codex CLI 已在本地和服务器两端验证通过
- OpenClaw Agent 已完成第一轮基础接入验证
- 共享目录中已形成阶段状态文档体系

### 方案 3.0 的状态

方案 3.0 的核心，不再是"把环境搭起来"，而是：

**把环境升级为 AI-first、高授权、人工主验收的高权限协作开发环境。**

当前已落地为：
- 灵犀不再只是文档助手，而是服务器侧主执行代理
- ChatGPT 负责方案、规则、文档、任务拆分
- Codex CLI 负责只读分析、辅助 review 与轻量生成
- GitHub 共享目录成为多角色协作控制台
- 本地人工主要负责方向控制、审阅、验收、节奏管理

## 四、当前建议保留的边界

### 1. 默认允许 AI/灵犀做的事

- 读取整个 repo
- 修改 docs/、tools/、scripts/、README 及小型辅助文件
- 生成和更新共享目录状态文档
- 生成与升级 change summary / handoff / regression summary / status panel
- 做小范围功能增强
- 做小范围模块化整理
- 做分支内 commit / push
- 生成 demo 入口和展示说明

### 2. 仍建议人工确认后再做的事

- 改 main
- 删除大量文件
- 大范围重构
- 改 systemd
- 改 OpenClaw 核心运行配置
- 升级 OpenClaw 镜像
- 改密钥、token、.env 真值

### 3. 当前不建议做的事

- 为了"更自动化"而做高影响系统级改造
- 过早把测试仓升级为重型平台
- 在共享目录里堆敏感配置和大文件

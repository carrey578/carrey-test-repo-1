# 140-project-routing-guide

> 项目类型路由指南。指导不同项目类型如何选择执行模型。

---

## 项目类型路由总览

| 项目类型 | 默认路由 | 升级条件 | 边界 |
|----------|----------|----------|------|
| 小型企业级数据工程 / AI 应用 | ChatGPT 规划 + Coding Plan 执行 | 跨文件复杂 pipeline / 深度读仓时申请外部模型 | 不要让外部模型做规划 |
| 网站 / Web App / PC 小工具 | ChatGPT 规划 + Coding Plan 常规实现 | 复杂状态管理 / 大段重构时申请外部模型 | 简单页面不要升级 |
| 手机 App / 小游戏 / 创业 MVP | 先小骨架、先低成本模型 | 只有高价值短任务才申请外部模型 | 不要一开始就上外部模型 |
| 量化投资分析 / 研究脚本 | 低成本模型先跑框架与脚本草案 | 复杂回测结构或大段分析时申请外部模型 | 不要让外部模型做交易决策 |

---

## 详细说明

### 1. 小型企业级数据工程 / AI 应用

**默认路由**：
- 规划阶段：ChatGPT（你本地）
- 执行阶段：Coding Plan

**升级条件**：
- 需要分析整个代码库的 pipeline 逻辑
- 跨多个文件的复杂数据流重构
- 需要深度读仓理解现有架构

**边界**：
- ❌ 不要让外部模型参与规划决策
- ❌ 不要让外部模型直接写生产级 pipeline
- ✅ 规划你来做，执行默认模型，复杂分析才升级

---

### 2. 网站 / Web App / PC 小工具

**默认路由**：
- 规划阶段：ChatGPT
- 实现阶段：Coding Plan

**升级条件**：
- 复杂状态管理逻辑（如 Redux/Vuex 大规模重构）
- 大段代码重构（跨 10+ 文件）
- 需要深度理解第三方库/框架内部

**边界**：
- ❌ 简单页面实现不要升级
- ❌ 小修小补不要升级
- ✅ 只有"不做会出问题"的大改动才升级

---

### 3. 手机 App / 小游戏 / 创业 MVP

**默认路由**：
- 先用小骨架
- 先用低成本模型

**升级条件**：
- 只有高价值短任务才申请外部模型
- 例如：核心算法实现、关键性能优化

**边界**：
- ❌ 不要一开始就申请外部模型
- ❌ 不要让外部模型做 MVP 整体架构
- ✅ 先用默认模型跑通 MVP，验证后再优化

---

### 4. 量化投资分析 / 研究脚本

**默认路由**：
- 研究框架与脚本草案：低成本模型
- 回测代码：低成本模型

**升级条件**：
- 复杂回测结构设计
- 大段策略分析
- 需要多文件联合分析

**边界**：
- ❌ 不要让外部模型做交易决策
- ❌ 不要让外部模型生成下单代码
- ✅ 只让外部模型做分析，不做执行

---

## 通用规则

### 升级流程
1. 灵犀评估是否需要升级
2. 灵犀发送授权申请（模板见 132）
3. 你授权后，灵犀执行任务
4. 任务完成后必须回退

### 回退要求
- 外部模型任务完成后**必须**立即回退
- 回退脚本：`/root/workspace/config/model-routing/restore-default-route.sh`
- 验证：`APPROVED=0`，路由回到 Coding Plan

### 禁止事项
- 未经授权，不得使用外部模型
- 不得在任务完成后继续使用外部模型
- 不得将外部模型设为默认路由
- 不得让外部模型参与交易决策

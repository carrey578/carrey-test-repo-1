把灵犀的长期职责做正式收口：
- 默认可直接做什么

第4批的目标不是继续证明 AI 能做事，而是：

**把前3批形成的开发能力，收口成“至少1个完整小功能闭环 + 最小测试/回滚/交接体系”。**

## 6.2 第4批核心目标

1. 完成 1 个更完整的小功能闭环
2. 建立最小测试入口
3. 建立功能回归检查清单
4. 建立最小回滚/恢复手册
5. 固化 verify / handoff / change summary 模板

## 6.3 第4批任务规划表

| 模块         | 目标                          | 主要执行者         | 输出                                     | 验收标准                     |
| ------------ | ----------------------------- | ------------------ | ---------------------------------------- | ---------------------------- |
| 功能闭环补强 | 补齐 1 个小功能的完整交付链路 | 灵犀主做，人工验收 | 功能实现 + 使用说明 + 验证文档 + handoff | 可跑通、可解释、可交接       |
| 最小测试入口 | 建立轻量测试或验证入口        | 灵犀主做           | verify script / verify guide             | 可重复执行，结果可复查       |
| 回归检查清单 | 建立改动后的检查项            | 灵犀主做           | checklist 文档                           | 至少覆盖正常/异常/输出存在性 |
| 回滚恢复手册 | 明确最小恢复操作              | 灵犀主做，人工复核 | rollback / recovery guide                | 人工可按文档执行恢复         |
| 模板固化     | 固定功能开发相关模板          | 灵犀主做           | template 文件组                          | 后续任务可直接复用           |

### 第三步

### 第四步

## 6.5 第4批完成标志

满足下面 5 条，可视为第4批完成：

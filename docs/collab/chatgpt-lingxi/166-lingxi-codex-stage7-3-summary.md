## 一、阶段目标

阶段 7.3 的原始目标是：

在 **本地 Windows + Codex CLI** 路线下，完成一次**低风险、单文件、可回退、可验收**的最小写入试验，用来验证本地 Codex 是否已经具备轻量脚本协作能力。

本轮原计划的核心边界为：

- 仅在 `work/lingxi-codex-bootstrap` 分支操作
- 以 `tools/dev-entry.ps1` 为主要目标文件
- 仅允许 help / 文案 / 标题类修改
- 不改命令名、参数名、路径逻辑、函数签名和核心行为
- 先看 diff，再跑本地验收，再决定是否提交

这一步的意义是：

1. 证明失败路径可用
2. 防止把“未被可信验收证明的改动”直接推上远端
3. 保持试点边界内的保守节奏

## 四、加固动作

在回退之后，为了让本轮“通过”具备真实可信的依据，又进行了验收链加固。

本轮额外修复了以下两个文件：

### 1. `tools/verify-dev-entry.ps1`

修复方向：

- 稳定捕获 `dev-entry.ps1` 的输出
- 按明确布尔结果判断测试是否通过
- 减少 help 输出导致的误判

### 2. `tools/repo-health-check.ps1`

修复方向：

- 通过独立 PowerShell 进程运行子脚本
- 更可靠地读取子脚本退出码
- 避免对子检查结果产生误汇总

这两个修复的目的不是扩张需求，而是补齐原 7.3 在现场暴露出的基础缺口，使“阶段通过”具备真实可复验性。
